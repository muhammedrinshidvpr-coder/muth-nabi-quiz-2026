# Muth Nabi Mega Quiz 2026 — Implementation Plan

## Goal

Build a polished, mobile-first registration site for Muth Nabi Mega Quiz 2026 at TKM College of Engineering, host it on GitHub Pages and Vercel, and provide an Apps Script integration that saves registrations into a private Google Sheet.

## Requirements

- Event page title: **Muth Nabi Mega Quiz 2026**; organizer/campus: **TKM College of Engineering**.
- Online quiz: **5 October 2026 at 8:30 PM IST**.
- Eligibility: students of TKM College of Engineering only.
- Use a complete event landing page inspired by the reference page’s forest-green/gold palette, hero, event information, and registration card; make it responsive, accessible, visually polished, and quick to load.
- Collect required fields: Name, Mobile Number, Email, Department, Class, Gender, and a required confirmation that the student has joined the WhatsApp group.
- Department is a dropdown of TKMCE departments, `PG`, and `Other / not listed`; Class remains free text; Gender options are Male and Female only.
- Preserve the WhatsApp group link in the registration success state; do not redirect automatically.
- Save submissions to a new organizer-owned Google Sheet; do not expose the sheet to registrants.
- Create public repository `muth-nabi-quiz-2026` under `muhammedrinshidvpr-coder`.
- Publish with GitHub Pages. CI validates pull requests and deploys successful changes merged to `main`.

## Scope and Boundaries

### In scope

- Static, dependency-light event page and form.
- Google Apps Script submission handler intended to be copied/deployed from the organizer-owned Sheet.
- Required WhatsApp-join acknowledgement recorded with each saved registration.
- Use the supplied ProfSummit logo artwork from the PDF as the linked header brand asset.
- Sheet setup instructions, local preview instructions, and deployment instructions.
- GitHub Actions validation and Pages deployment workflow.

### Out of scope

- Creating or accessing the user's Google Sheet, deploying Apps Script, or configuring Google account permissions on the user's behalf.
- Inventing prize amounts, registration closing date, contact details, college branding assets, or extra event policies.
- Collecting or storing registrations in the public GitHub repository.

### Must follow

- Keep the spreadsheet private and keep any Sheet identifiers in Apps Script configuration, not committed frontend files.
- Do not claim a registration is saved until the submission flow reports success.
- Preserve keyboard navigation, semantic labels, visible focus states, and readable contrast.
- Do not add unnecessary frontend frameworks, remote images, or heavy runtime dependencies.

## Data Contract

One registration contains:

| Field | Type | Validation |
|---|---|---|
| name | string | Required, trimmed, non-empty |
| number | string | Required; accept a reasonable international phone format |
| email | string | Required; valid email format |
| department | enum | Required TKMCE department option, `PG`, or `Other / not listed` |
| className | string | Required, trimmed, non-empty (examples such as M5A) |
| gender | enum | Required: `Male` or `Female` |
| joinedWhatsApp | boolean | Required; true only when the student checks the join confirmation |
| submittedAt | timestamp | Generated by the Apps Script handler |

The Sheet columns are `Submitted At`, `Name`, `Number`, `Email`, `Department`, `Class`, `Gender`, and `WhatsApp Joined`.

WhatsApp membership is self-confirmed by a required checkbox and is not independently verified by WhatsApp.

## Submission Flow

1. Browser validates required fields and formats, then sends a URL-encoded registration to the configured Apps Script web-app endpoint.
2. Apps Script validates the fields again, appends a timestamped row to the bound private spreadsheet, and returns an explicit success/failure result.
3. The page presents the confirmation state only on success; on failure it preserves the entered values and displays a retryable error.

## Pre-decisions

- **Frontend:** use semantic HTML, CSS, and vanilla JavaScript so the Pages artifact stays small and fast.
- **Visual direction:** use the reference's forest green, warm cream, and gold as inspiration, paired carefully with the supplied ProfSummit logo artwork; do not invent a TKM logo.
- **Hosting:** GitHub Pages and Vercel; GitHub Actions validates pull requests and deploys Pages, while the Vercel project is connected to the GitHub repository for automatic main-branch deployments.
- **Sheet integration:** use a bound Apps Script project and a same-origin-safe form submission/response bridge rather than exposing Google credentials in browser code.
- **Page content:** show event title, online format, schedule, eligibility, and registration. Omit prizes and other unspecified details.
- **Repository:** public `muth-nabi-quiz-2026` under the currently authenticated GitHub account.

## Task Breakdown

1. Create the minimal static site structure, event landing page, responsive styles, registration form, and accessible status states.
2. Add Apps Script handler and setup documentation for the private Sheet, web-app deployment, and endpoint configuration.
3. Add meaningful validation/registration-flow checks and GitHub Actions PR checks plus GitHub Pages deployment.
4. Run checks, inspect the site at desktop and mobile sizes, then create the public GitHub repository and push the verified project.

Dependencies: task 1 precedes task 3; task 2 can proceed alongside task 1; repository publishing follows successful verification.

## Verification

- Run project checks and confirm they fail for invalid required fields and pass for a valid registration payload.
- Verify a valid submission reaches the handler and yields a success confirmation; verify a rejected/failed submission does not show success and retains the form values.
- Verify the site builds and works at the GitHub Pages project path (not just `/`).
- Inspect responsive layout and keyboard form use at mobile and desktop widths.
- Validate the Actions workflow syntax and confirm its build job succeeds before publishing.

## Acceptance Criteria

- A student must confirm WhatsApp group membership before submitting; the acknowledgement is saved alongside the six student fields.
- Department uses a dropdown, Gender only offers Male/Female, and Class remains free text.
- A student can complete the form on desktop or mobile, receive an animated success confirmation after a successful Sheet write, and access the compact WhatsApp join button.
- Invalid inputs are blocked with accessible feedback; failed saves can be retried without re-entering data.
- The site clearly displays the confirmed event schedule and eligibility without invented prizes/deadlines.
- The public GitHub repository contains no Sheet rows, credentials, or private identifiers.
- Pull requests run checks; merges to `main` deploy to GitHub Pages and Vercel.
- README contains the Google Sheet/App Script setup instructions and hosting workflow details.
